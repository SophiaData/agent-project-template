# Documentation workflow

1. Read docs/documentation.md and docs/AGENTS.md if the project defines one.
2. Identify the correct owner and tier for each fact before writing.
3. Describe current behavior, contracts, ownership, defaults, failure behavior and compatibility.
4. Keep one authoritative home for each rule; link rather than duplicate lower-level detail.
5. Update docs in the same change as code, configuration, API or data-contract changes.
6. Verify links, examples, commands, generated references and diagrams.
7. Use docs/decisions/ for durable rationale and docs/compatibility.md for externally visible breaks.
